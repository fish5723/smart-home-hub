## 已知边界

- 30fps 是素材和播放器目标帧率；实际显示帧率受 LCD/总线/解码/SD 读取共同限制，应以真机 SELFTEST 统计为准。
- 壁纸 JWP 源生成在根 `ui/wallpaper/`（9 场景 day/night + `_02/_03` 变体，共 57 个 .jwp）—— **不入库**：单个实测最大 82 MB、全量约 1.4 GB，属本地素材（自行拷到 SD 卡），仓库只保留 `test/sample.jwp`（18 KB 样例）；运行时从 SD `/sdcard/wallpaper` 加载，现场只部署需要的场景目录。`.gitignore` 已按真实路径设规则：忽略 `ui/wallpaper/**/*.jwp` 但保留 `!ui/wallpaper/test/sample.jwp`（旧规则指向不存在的 `ui/assets/wallpaper` / `ui/assets/video`，已删除；见 docs/16 §一.14）。
- 阶段四不得先改 UI；应从执行器、规则和安全状态开始，沿用现有协议与设备影子状态。

## 阶段四入口

阶段四目标是“执行器联动与本地场景引擎”：

1. 建立执行器控制层，含状态回读、超时和互锁。
2. 建立离线可运行的条件—动作规则引擎。
3. 将规则持久化到 NVS，并定义版本迁移策略。
4. 完成水泵超时保护、雨天跳过灌溉和断电安全状态。
5. 用 GPIO 打点测量屏幕操作到执行器动作延迟，目标小于 200ms。

阶段四第一步应先阅读 `docs/00-路线图.md`、`docs/05-决策记录-ADR.md`、协议组件和 F103 继电器/水泵实现，再写 ADR 和最小状态机测试。
