| 指标 | 实测值 | 判定 |

**完整性交叉验证方法**（面试考点）：两端的计数器是独立记账的——P4 的 tx/rx 与 F103 的 rx/tx 互相咬合（差值恰好等于两次统计快照的时间差 × 速率），任何一端丢帧或复位都会破坏这个守恒关系。

## 4. 故障注入（2C-2）

固定随机种子（可复现），随机帧类型偏选 `ACTUATOR_CMD` 以加重"误执行"后果：

| 注入 | 次数 | 检出 | 误执行/伪造帧 | 结论 |
|---|---|---|---|---|
| 单比特翻转（位置含 SOF/CRC 全帧） | 1000 | 906 次 CRC 检出 + 94 次落 SOF 安全忽略 | **0** | 全部安全 |
| 随机丢 1 字节（5 帧连续流中） | 1000 | 帧内超时 abort 后 **1000/1000** 恢复 | **0** | 全部安全 |

> "零误执行"判定：任何被投递的帧必须与发送的某一帧逐字节一致；类型/序列/载荷任一不同即记误执行。

## 5. 物理层故障测试（2C-4，2026-10-02）

**方法**：LINK UP 稳定后拔掉 F103→P4 方向杜邦线（PA9），观察 P4 链路状态机；重插观察恢复。实测日志：

```
I (25047) app_proto: RX  type=0x10 seq=3          ← 最后收到的帧
I (28049) app_proto: LINK UP -> DEGRADED (was 5864 ms)   ← 拔线后 3s
I (31049) app_proto: LINK DEGRADED -> DOWN (was 2999 ms) ← 累计 6s 判死
I (31059) app_proto: RX  type=0x10 seq=9          ← 重插后首个到达帧
I (31059) app_proto: LINK DOWN -> UP (was 10 ms)  ← 重连延迟 10ms
```

| 检查项 | 期望 | 实测 |
|---|---|---|
| 重连延迟 | <2s | **10ms** |
| 恢复后解析 | 无半帧/误解析 | seq=9 帧完整解析，字段正常 |
| 执行器误动作 | 0 | 0 |
| 丢帧账目 | 守恒 | seq 4→9，拔线 5s 丢 5 帧 |

**阈值权衡记录**：检测总时长 6s（3s+3s）慢于"越快越好"的直觉，是刻意选择——心跳间隔 2s 意味着正常静默窗口已接近 2s，阈值取 3s 才不误报；且 DEGRADED 状态在 3s 时已可用于 UI 提示，6s 判死只影响"离线灰态"的最终确认。参数与依据已写入 `docs/03` §6.3/§9。
