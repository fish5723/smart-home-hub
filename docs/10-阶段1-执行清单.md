## C. 并行技术债（P4 侧，不阻塞阶段 1 验收）

来自本轮的阶段 0 代码审查（阶段 0 代码审查要点，无独立文档，要点已并入本清单）。**建议在阶段 3（做 UI）之前修掉**，否则会以"偶发画面撕裂"的形式表现出来且极难归因：

- [ ] **摄像头双缓冲撕裂**：传感器 50fps（20ms/帧）而消费端 33ms/帧 → `csi_get_new_buffer` 翻转缓冲时 DMA 会覆写正在被 CPU 读取的那一块；且 `s_frame_buffer_sel` 非 `volatile` 却被跨上下文读取，`camera_get_frame_buffer()` 可能返回正被 DMA 写入的缓冲。
  **修法**：三缓冲 + 所有权交接（消费完才归还），或把消费周期压到 ≤20ms，或降分辨率。
- [ ] **ISR 内 1MB memcpy**：`camera.c` 的 `csi_frame_finished()` 在 `IRAM_ATTR` 里 memcpy 最多 1MB（捕获路径），而 `camera_manager.c` 自己的注释写着"ISR 中绝对不能调用 memcpy 拷贝大量数据"——自相矛盾。
  **修法**：ISR 只给信号量，拷贝移到任务上下文（拷贝期间停流或走所有权机制）。
- [ ] **1MB memcpy × 30fps 跑在 LVGL 定时器里**（约 30MB/s），会直接吃掉 LVGL 任务预算，与阶段 3 的 30fps 目标冲突。
  **修法**：零拷贝（两个 PSRAM 缓冲之间换指针）或降分辨率/帧率。

## 🚧 常见卡点速查

| 现象 | 优先怀疑 | 处理 |
|---|---|---|
| ADC 读数仍抖动 | 地线布局 / 电源噪声（软件滤波已加） | 模拟地与数字地分开、单点汇接；继电器动作时观察是否跳变 |
| MQ 读数饱和不变 | **没有分压**，5V 直接进了 3.3V 引脚 | 立即断电检查分压电阻 |
| I2C 挂死 | OLED 未插 / 总线被拉低 | 换有限超时后能报错，再加总线恢复（翻转 SCL） |
| DHT11 偶发失败 | 微秒延时被中断打断 | T-09：临界区关中断 + TIM 基准 |
| W25Q64 写入后读回不一致 | 未检查 WEL / 未等 tPUW | T-10 |
| IWDG 复位后行为异常 | 复位原因未区分 | T-05：先读 `RCC_CSR` 再初始化 |
| 烧录后无输出 | USART3(PB10/PB11) 波特率 / Retarget | 确认 115200 且 `RetargetInit(&huart3)` 已调 |

> 💡 **本阶段的调试原则**：F103 侧代码是继承来的，**出问题先问"这是原实现的问题还是我改出来的"**——用 `git stash` 或对比 `E:\summer_project\smart_home` 的原始实现能快速定位。
