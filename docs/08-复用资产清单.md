## 0. 一句话结论

**两个前序工程的 BSP 层与平台层价值极高（尤其 P4 侧），应用层价值为零。**

| 侧 | 可复用度 | 说明 |
|---|---|---|
| **ESP32-P4（learning-box）** | **BSP/平台层 ~70% 可直接继承** | 同款板子、同款屏、同款摄像头。显示链路、触摸、LVGL 桥接、Wi-Fi hosted、摄像头+ISP+硬件 JPEG、字体双层加载、C6 固件 OTA、任务调度平台——全部是已验证过的代码。应用层（NES 模拟器 / 教育 UI / 云端搜题）与中控面板无关，**一律不碰** |
| **STM32F103（smart_home）** | **~50%，骨架可留、血肉需换** | 引脚/外设初始化完全正确可继承；BMP280、W25Q64 驱动质量好；11 类外设驱动已存在但质量参差。**七项关键能力全部缺失**：IWDG 看门狗、复位原因诊断、EEPROM 驱动、MQ 传感器 R0 标定、ADC 滤波、TIM/PWM、FreeRTOS |

**最重要的一条判断**：不要"fork 整个工程然后删业务"。正确做法是**新建干净仓库，只挑 A 档模块逐个搬进来，搬运时当场修掉审计报告里已定位的缺陷**。理由见 §4 与 §6。

### ⚠️ 三条来自前序工程的硬约束（不遵守会踩坑）

1. ~~**`esp_hosted` 版本必须锁 2.9.6**~~ → **2026-10-18 决策（B1）：承认实测已通过的 3.0.9，不回退**，并在 `idf_component.yml` 精确锁定 `==3.0.9` / `==1.6.5`（此前只写范围，component manager 会拉到 3.0.9）。历史依据保留：原工程注释称"经版本回归验证：**2.12.9 会必现 SDIO 258 错误**，2.9.6 无此问题"。
2. **SD 卡（SDMMC Slot 0）必须在 Wi-Fi（C6 SDIO，Slot 1）之前初始化**。两者**共享时钟分频器**，顺序反了会导致 C6 复位 → `netif_add` 崩溃。原工程是靠 `system_init.c` 的初始化顺序规避的，**没有运行时守卫**（审计 H1 未修）——本项目要补一个守卫。
3. **`CONFIG_ESP_HOSTED_TRANSPORT_RESTART_ON_FAILURE` 要设为 `n`**。原工程设成 `y` 时，SDIO 258 错误会直接 `esp_restart()` 造成 boot loop（因此他们的 `https_test_task` 被永久禁用）。这个配置对长期运行的中控面板是灾难。

### 触摸与摄像头的总线冲突（已在原工程解决，继承即可）

`I2C_NUM_1`（GPIO7/8）**被 GT911 触摸和 OV5647 的 SCCB 共用**，SCCB 频率降到 10kHz，通过 `touch_get_i2c_bus()` 取总线句柄。不要另开 I2C 控制器。

## 3. 必须先修的缺陷（带缺陷复用 = 埋雷）

### 3.1 🔴 最高优先级：电子锁控制必须重写

> **结论（2026-10-18 修订）**：锁**确定不做**（模块买错），`app_lock` / `bsp_lock` 已于 2026-10-18 删除，调度器 LOCK 任务一并移除。以下分析保留为历史记录；PB8 现由 `act_manager` 独占写、保持默认锁定电平。

原工程的锁控制**存在三个独立问题**，任何一个都会烧硬件或让功能不可用：

```c
// BSP/LOCK/bsp_lock.c —— 全部 14 行，没有任何限时通电保护
void BSP_LOCK_Unlock(void) { HAL_GPIO_WritePin(GPIOB, GPIO_PIN_8, GPIO_PIN_SET); }
```
```c
// APP/lock/app_lock.c —— 只要标志为 1，PB8 就【持续】保持高电平
if (g_lock_unlocked) { BSP_LOCK_Unlock(); } else { BSP_LOCK_Lock(); }
```

| 问题 | 后果 |
|---|---|
| ① **无脉冲限时** | 若是 SMA 钛丝锁（XG07E 类），**持续通电会永久损坏钛丝**；若是电磁锁则是持续大电流 |
| ② **`APP_LOCK_SetUnlocked()` 全工程无外部调用者** | 唯一调用是 `APP_LOCK_Init()` 里的 `SetUnlocked(0)` → **固件里锁是永久锁死的，根本无法开锁** |
| ③ **PB8 配置为开漏(OD) + 上拉** | 开漏只能灌电流（约 20mA 量级），**物理上驱动不了锁这类负载**，必须加 MOSFET/驱动模块 |

**处理方式（2026-10-18 作废）**：~~整个 `BSP/LOCK` + `APP/lock` 重写。驱动路径改为 `GPIO → MOSFET 模块 → 锁`，通电动作用**独立硬件定时器**限时（100~500ms 脉冲）并由看门狗兜底，软件层二次超时保护，动作后回读状态。~~ → **改为"删除"**：锁确定不做，`app_lock` / `bsp_lock` 已删除，PB8 仅由 `act_manager` 独占写（默认锁定电平）。

**❓需要你确认的硬件事实（2026-10-18 已确认）**：原工程代码里**没有任何 "XG07E"、"钛丝"、"电磁锁" 的字样或数据手册引用**，单看代码无法判断这个 PB8 到底接的是什么负载。~~请你确认：**当时接的是 XG07E 钛丝锁，还是普通电磁锁/继电器？** 这决定脉冲宽度和驱动电路的设计。如果不确定，按最保守的"钛丝锁"处理（短脉冲 + 限时）。~~ → **已确认为"锁模块买错、不做锁"，本节设计讨论作废。**

### 3.2 🟠 从审计报告继承的未修缺陷

`smart-learning-box` 做过三份审计报告（`AUDIT_REPORT.md` / `CRASH_AUDIT_REPORT.md` / `THREAD_AUDIT_REPORT.md`），**约六成问题已修**。以下是**确认未修、且会带进本项目**的条目——搬运时必须先修：

| 编号 | 文件 | 问题 | 影响 |
|---|---|---|---|
| **M6** | `main/app/font_loader/font_loader.c:165-200` | 加载字体前 `esp_task_wdt_deinit()`，加载 7 个字体约 **44 秒无看门狗**，然后才 `init` 回 5s | 字体解析卡死 → 系统永久挂起。**改法**：用 `esp_task_wdt_reconfigure()` 延长超时 + 每字体 `esp_task_wdt_reset()`，不要 deinit |
| **H1** | `main/bsp/storage/sd_card.c` | 无 SD 卡/Wi-Fi 时钟冲突的运行时守卫，仅靠初始化顺序规避（见 §1 约束 2） | 运行期重挂载 SD 卡会打乱 C6 的 SDIO。**加守卫**：重挂载前检查 `wifi_is_connected()` |

| **N7** | `main/manager/http_manager.c` | `resp_data` 分配失败后继续使用 | **要修**（本项目的 HTTP/OTA 可能复用此模块） |
| **M4** | `main/manager/camera_manager.c:330+` | `preview_stop` 超时后 `vTaskDelete` 强杀任务，强杀瞬间帧缓冲可能泄漏 | 长时间运行会累积约 1MB PSRAM 泄漏。**改成协作式退出标志** |

> **不搬 NES/OCR/教育业务，就自动消掉了一批缺陷**（B2/B3/M3/N2/B5 都在业务代码里）。这也是"只挑 A 档"而不是"fork 全量"的关键理由。

### 3.3 看门狗策略建议（新项目统一）

原工程两处互相打架。本项目建议**统一为**：
- 主任务注册进 TWDT，超时 **10 秒**（不是 5 秒也不是 60 秒）
- 耗时操作（字体加载、OTA、图像初始化）**临时 `esp_task_wdt_reconfigure()` 放宽到 60 秒**，操作完恢复，**全程不 deinit**
- 加**任务看门狗**监控关键任务（协议收包、UI、网络），单任务卡死也能被发现
- 配 `CONFIG_ESP_TASK_WDT_PANIC=n`（先重启+记日志，便于定位）

## 4. 🔴 安全事件：必须先处理，再谈复用

`smart-learning-box` 的 `sdkconfig` 与 `sdkconfig.defaults` 里**明文硬编码了**：
- 真实 Wi-Fi SSID 与密码
- 豆包（ark）API Key（`CONFIG_SMARTBOX_LLM_API_KEY`）
- 硅基流动 API Key（`CONFIG_SMARTBOX_VISION_API_KEY`）

而该工程**已经推送过 GitHub**。这意味着**这些密钥应视为已泄露**。

**必须做的三件事**（按顺序）：
1. **现在就去轮换/吊销这些密钥**（改 Wi-Fi 密码、在豆包和硅基流动后台重置 Key）。这一步与项目进度无关，越早越好。
2. 本项目**绝不复制** `sdkconfig` / `sdkconfig.defaults` 的敏感段。密钥一律走 **Kconfig 默认空 + 环境变量 + 本地 `sdkconfig.local`（加入 `.gitignore`）**。
3. 历史泄露无法通过删文件解决（Git 历史里还在）。如果那个仓库还要公开，需要 `git filter-repo` 重写历史 + 强制推送；更简单的做法是**把该仓库设为私有**。

## 6. 搬运策略（推荐做法）

**不要**：`cp -r smart-learning-box smart-home-hub` 然后开始删 NES。这会把 40+ 个业务文件、15.6MB 字体、一屁股未修缺陷一起带进来，而且你会花几天在"删干净"上。

**要**：新建干净工程，**只搬 A 档文件，每个模块搬进来时当场做三件事**：① 把硬编码引脚接到 Kconfig；② 修掉 §3.2 里属于它的缺陷；③ 写一个最小验证用例证明它在新工程里能跑。

推荐顺序（每步都能独立验证，坏了立刻知道是哪一步）：

## 7. 分区表必须重排（P4）

原 `partitions.csv` 的致命问题：

```
nvs,      data, nvs,        0x9000,   0x6000
phy_init, data, phy,        0xf000,   0x1000
factory,  app,  factory,    0x10000,  0xA00000   ← 只有 1 个 app 分区
slave_fw, data, undefined,  0xA10000, 0x200000   ← C6 固件暂存
storage,  data, fat,        0xC10000, 0x3F0000
```

- ❌ **没有 `ota_0`/`ota_1`** → 物理上不支持 A/B OTA 与回滚
- ❌ **没有 `ota_data`** → 连 `esp_ota_mark_app_valid_cancel_rollback()` 都不可用
- ❌ **没有 `coredump` 分区** → panic 时拿不到崩溃调用栈（原工程 `crash_log.c` 只能打串口）
- ⚠️ `nvs` 只有 24KB，偏小（配置 + 场景规则 + 版本记录都要放）

本项目需要：双 OTA 槽（各 4MB 足够，现有 factory 用了 10MB）+ `ota_data` + `coredump`。16MB Flash 完全够，但要**重新规划一遍并做一张 Flash 地图**（列入阶段 H 的交付物）。
