# 阶段四开发 Prompt

你正在继续 Smart Home Hub 项目的阶段四开发。阶段三已经完成并通过 ESP32-P4 真机验证。不要重新设计 UI，不要切换 IDF 版本，不要恢复阶段三的 HTML/视频原型工作。

## 固定基线

- 工作区：`仓库根目录`
- P4 工程：`firmware/p4-hub`
- 工具链：ESP-IDF 6.1，由 `tools/activate_idf.ps1` 配置
- 唯一 P4 构建目录：`firmware/p4-hub/build`
- 构建：`cmd /c tools\p4build.bat`
- 芯片：ESP32-P4 + 板载 ESP32-C6
- 显示：1024×600 JD9165BA MIPI-DSI，触摸 GT911

## 阶段四目标

实现执行器联动与本地场景引擎：

1. 执行器抽象：继电器、水泵、蜂鸣器等（**锁不做**：模块买错，2026-10-18 已删 `app_lock` / `bsp_lock`，PB8 仅由 `act_manager` 独占写），必须有命令、状态回读、超时和互锁。
2. 本地规则引擎：条件、动作、优先级、去抖/迟滞、冷却时间和失败处理。
3. NVS 持久化：规则版本、校验、掉电恢复和迁移。
4. 安全：水泵最长运行时间、重启/断电安全态、通信断开时的处理（**本地灌溉兜底现禁用：`APP_IRR_LOCAL_FALLBACK_ENABLE=0`，断链仅强制关泵，不做本地双阈值**）。
5. 可测量：GPIO 打点记录 UI 点击到执行器确认延迟，目标 <200ms（**当前仅完成打点，尚无实测数字，待实测**）。

## 工作约束

- 先读 `docs/13-阶段三验收与阶段四交接.md`、`docs/00-路线图.md`、`docs/05-决策记录-ADR.md`。
- 复用协议和设备影子状态，不复制一套状态模型。
- 先写 ADR、接口和纯逻辑单测，再接硬件 GPIO。
- 任何 UI 改动必须证明是执行器状态反馈所需；不得借机重做页面。
- 每次只做一个可验证变量；真机烧录由用户手动完成。
- 不能把 220V 接入项目；所有执行器按 5V/12V 直流安全边界验证。
- 构建失败先检查环境和 `build/` 缓存，不要创建第二个 P4 构建目录。

## 完成定义

- 至少 5 条规则可配置并持久化。
- 断网时规则仍能本地触发。
- 水泵超时和互锁测试通过（⚠️ 本地灌溉兜底开关为 0、水泵实物未接，暂无实机验证）。
- 重启/断电后执行器进入文档定义的安全状态。
- 有自动化单测、真机日志和延迟数据（端到端延迟目前**仅有打点、待实测**）。
- 更新阶段四文档与 ADR 后再提交 Git。
