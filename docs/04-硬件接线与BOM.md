## 3. ⚠️ 电平与信号调理（最容易烧板的地方）

### 3.1 MQ 系列传感器输出必须分压
MQ-135/MQ-4 模块通常 **5V 供电**，其模拟输出在洁净空气中约 1~3V，但在高浓度环境下**可能接近 5V**。
- **F103 的 ADC 引脚是 3.3V 满量程，且多数引脚不是 5V 容忍！** 直接接入可能损坏 IO。
- **解决**：串联分压。用 `R1=10kΩ`（信号侧）、`R2=20kΩ`（到地）→ 分压比 2/3，5V → 3.33V。
  - 更稳的做法：`R1=10k, R2=10k`（÷2），5V→2.5V，牺牲一点分辨率换安全余量。
- **软件侧同步换算**：`实际电压 = ADC 读数 × (R1+R2)/R2`

### 3.2 执行器驱动
| 负载 | 驱动方案 | 必备保护 |
|---|---|---|
| 继电器模块 | 模块自带光耦/三极管，GPIO 直连 IN 脚即可 | 模块的 VCC 用 5V（不是 3.3V），GND 与 MCU 共地 |
| 水泵（经继电器） | 继电器触点开关 | 触点两端并 **RC 吸收/续流二极管**（直流感性负载），否则断开会拉弧、干扰 MCU |
| ~~钛丝锁~~ | **不接入**（2026-10-18 决策 B4，模块买错） | 原计划 MOSFET + 续流二极管方案不再推进，见 `docs/16` |
| 蜂鸣器 | GPIO + 限流电阻 或 三极管 | 无源蜂鸣器串 100Ω |

### 3.3 共地问题
**所有子系统的 GND 必须共地**（P4、F103、C3、传感器、执行器电源）。这是 90% 的"通信不通/数据乱跳"的根因。
- 但**模拟部分（MQ 传感器）与数字开关部分的地线走线要分开，最后单点汇接**，否则继电器动作会让 ADC 读数跳变。
- 如果发现 ADC 抖动，先在固件里做多次采样取中值 + 剔除极值，再考虑硬件改进。

### ⚠️ 三条必须继承的硬约束（违反会踩坑）

1. **`esp_hosted` 必须锁 `3.0.9`**（配 `esp_wifi_remote 1.6.5`）。历史背景：前序工程锁的是 2.9.6，注释写明"经版本回归验证：**2.12.9 会必现 SDIO 258 错误**"。但新工程实测走的是 **3.0.9**，且该版本**配置符号已更名**——故必须写**精确锁定**（`==3.0.9` / `==1.6.5`），**不要写范围依赖**（范围会拉到 3.0.9 却不锁定）。
2. **SD 卡必须在 Wi-Fi 之前初始化**。`SDMMC Slot 0`（SD 卡）与 `Slot 1`（C6 的 SDIO）**共享时钟分频器**，顺序反了会让 C6 复位 → `netif_add` 崩溃。前序工程只靠初始化顺序规避，**没有运行时守卫**，本项目要补。
3. **`CONFIG_ESP_HOSTED_TRANSPORT_RESTART_ON_FAILURE` 设为 `n`**。设为 `y` 时 SDIO 258 错误会直接 `esp_restart()` 造成 boot loop——对需要长期运行的中控面板是灾难。（前序工程正因为此永久禁用了它的 `https_test_task`。）

## 5. 电源树与电流预算 ⚠️ 必须算

### 5.1 电源树
```
12V/1A 适配器 ──┬──→ [12V 母线] ──→ 电源模块 (12V→5V) ──┬──→ [5V 母线]
                │                                          ├──→ 继电器模块 VCC (≈15mA/路 + 吸合 70mA)
                │                                          ├──→ 水泵 (峰值电流最大项！)
                │                                          ├──→ (原钛丝锁不接入——模块买错，2026-10-18)
                │                                          ├──→ MQ-135/MQ-4 加热丝 (各 ≈150mA@5V)
                │                                          └──→ P4 板 5V 输入 (经 USB-C 或 5V 脚)
                │
                └──→ 若电流不够：单独给 P4 用 USB-C 5V/2A 供电，12V 只带执行器与传感器
```
**推荐做法**：**P4 单独用 USB-C 5V 供电**，12V 支路只负责执行器与大功耗传感器。这样即使水泵启动造成 5V 母线瞬间掉压，也不会让主控复位。**这是"电源域隔离"，是很实用的工程经验。**

## 7. 安全红线（务必遵守）

1. **绝不切换 220V 市电。** 所有被控负载都必须是 12V/5V 直流。涉及市电需要专业隔离设计与断电操作，开发阶段不碰。
2. **上电顺序**：先测电源输出 → 再单独接 MCU 验证 → 最后接执行器。**永远不要在接好大功率负载的情况下第一次上电。**
3. ~~**钛丝锁限时通电**由硬件定时器兜底，且调试时先串一个电流表观察脉冲电流。~~ → **不接入**（2026-10-18 决策 B4，锁不做）；原"电流表观察脉冲"的调试步骤一并作废，见 `docs/16`。
4. **水泵不允许空转测试超过 10 秒**（无液体冷却会损伤泵体）。
5. **面包板不走功率电流**：水泵、继电器负载侧的线**直接焊接或走端子**（原列的"钛丝锁"已不接入）。MB-102 面包板的弹片额定电流通常只有 0.5~1A，大电流会发热、氧化、打火，造成随机复位——这种"玄学故障"极难排查。
6. **MQ 传感器加热丝工作时外壳会烫**，注意别用手直接碰。
7. 所有接线在改动前**先断电**。
