## 1. 时间线与推进节奏

建议每阶段 **1~1.5 周**，全项目 **13~16 周**。每周固定动作：

- **周初**：从本文复制该阶段任务到 `docs/journal/YYYY-MM-DD.md`，写下本周**一个可演示目标**
- **周中**：边做边记"卡点 + 怎么验证的"（面试素材的唯一可靠来源）
- **周末**：录 30 秒~2 分钟演示视频（存 `docs/media/`），更新本文阶段状态

**每阶段完成的定义（DoD）**——四项全过才算过：
1. 验收标准全部**实测**通过（有数据、有截图/视频）
2. 代码已提交，commit message 说清"做了什么、为什么"
3. 对应文档已更新（协议/架构/ADR/复用清单至少改动一处）
4. `docs/journal` 有本周记录

> ⚠️ **v2 新增纪律**：**搬运代码时不许跳过缺陷修复。** 前序工程的三份审计报告里还有约四成问题未修（详见 `docs/08-复用资产清单.md` §3.2）。带缺陷复用 = 埋雷，会在压力场景下变成随机崩溃，而且那时你已经忘了它是继承来的。

8. 连续 1 小时无死机，**DHT11 读取成功率 ≥95%**（当前实现在中断下会读错位）

### 阶段 2 · 双芯通信协议（P4 ↔ F103）——**本项目技术含金量最高的一环**　✅ **已完成**（验收：docs/13）

> 1.5~2 周。**协议规范 v2 已写好（`docs/03-通信协议规范.md`），直接实现。**

🎯 **目标**：定义并实现一套有文档、有容错、有测试的二进制协议。

📦 **交付物**
- 两侧协议栈（**各自独立实现**，不共用代码——这是"协议"而非"库"的证明）
- `tools/protocol_sniffer.py`：PC 端解析与可视化
- `tests/`：协议解析单元测试（PC 上跑，不依赖硬件）

✅ **验收标准**
1. 协议规范文档已定稿（帧头 `0xAA55`、版本、类型、序号、长度、CRC16-CCITT；ACK/重传/去重/心跳/指令 TTL）
2. **F103 侧收包从零建成**：USART1 + DMA + IDLE 中断收变长帧（当前 RX 完全没接、NVIC 里没有 USART1 中断）
3. **连续 24 小时 10Hz 上报 + 2s PING 保活：丢包率 0、重传率 <0.1%**，运行时可打印统计
4. **故障注入**：拔插杜邦线、短接 TX 到地制造噪声 → 自动恢复，断线重连 <2s，且**不产生半条指令导致执行器误动作**
5. **单元测试**覆盖 CRC16 标准向量（`CRC("123456789")=0x29B1`）、半包、粘包、超长帧、错帧、非法类型、重复 SEQ、TTL 过期 —— `ctest` 一键跑
6. **比特翻转 + 丢字节注入各 1000 次**，全部被 CRC 检出、零误执行
7. Python 工具能录包、解析成表格、画温湿度曲线

🧠 **学习点**：UART + DMA + IDLE 收变长帧（嵌入式最实用的收包技巧）、CRC16-CCITT 查表法与逐位法的性能差、**粘包/半包的本质与状态机解法**、序列号与去重表、重传窗口、指令 TTL 与幂等性、**错误码分层（传输层/应用层/执行层）决定定位问题的方式**、协议版本兼容与能力位图

💼 **简历映射**：**★ 通信协议设计 + 可靠性工程 + 单元测试与故障注入**
